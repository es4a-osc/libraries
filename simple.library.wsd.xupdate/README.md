# XUpdate更新库

基于 [XUpdate](https://github.com/xuexiangjys/XUpdate) 和 [XUpdateAPI](https://github.com/xuexiangjys/XUpdateAPI) 的 AndroidX 应用更新扩展库。两套上游能力统一交付，使用时只需引入本扩展库。

- XUpdate：`simple.library.wsd.xupdate`，提供基础更新流程及各环节定制。
- XUpdateAPI：`simple.library.wsd.xupdateapi`，提供快捷更新器与 Aria 暂停续传适配。

初次使用从下方的基础用法开始，不需要先了解另一套入口或实现定制接口。内部保留两部分的包名与职责。

## 基本使用

在窗口中放置名为“更新”的 `simple.library.wsd.xupdate.更新器` 组件，下面通过按钮发起检查：

```simple
事件 检查按钮.被单击()
	更新.检查更新("https://example.com/app/version.json")
结束 事件
```

默认使用 GET，发现更新后自动显示更新框，下载完成后请求系统安装。若要自行决定提示或安装时机，可将“自动提示”或“下载后安装”设为假，再处理“发现更新”或“下载完成”事件。

## 配置更新服务

最简单的方式是在 HTTPS 网站或对象存储中放置版本 JSON 和 APK，不需要运行专门的后端程序。发布新版本时，先上传 APK，再更新 JSON；使用 CDN 时同步处理缓存，保证检查接口能够取得最新内容。

检查地址返回 UTF-8 JSON，下载地址直接返回 APK 文件内容。下面的地址和版本仅为示例，使用时替换为实际发布信息：

```json
{
	"Code": 0,
	"UpdateStatus": 1,
	"VersionCode": 2,
	"VersionName": "2.0",
	"ModifyContent": "修复已知问题\n改善使用体验",
	"DownloadUrl": "https://example.com/app/2.0.apk",
	"ApkSize": 0,
	"ApkMd5": ""
}
```

| 字段 | 含义 |
| --- | --- |
| `Code` | 必填整数，`0` 表示接口成功；非零会触发检查失败。 |
| `UpdateStatus` | 必填整数：`0` 无更新，`1` 普通更新，`2` 强制更新，`3` 允许忽略此版本。 |
| `VersionCode` | 必填整数，对应 APK 的版本号及项目的 `version.code`；只有大于本机版本号才视为更新。 |
| `VersionName` | 有更新时提供的非空版本名称，用于显示，不参与版本大小比较。 |
| `ModifyContent` | 有更新时必填的更新说明，可使用 `\n` 换行。 |
| `DownloadUrl` | 有更新时必填的完整 HTTP 或 HTTPS APK 地址。 |
| `ApkSize` | 可选整数，单位为 KB，`1 KB = 1024 字节`；省略或 `0` 表示未提供大小。 |
| `ApkMd5` | 可选的真实 APK MD5，填写 32 位十六进制文本；省略或空文本表示不校验 MD5。 |

`ApkSize` 会转换为字节并参与严格大小校验，不能填写四舍五入的 KB 数。文件大小不是 1024 字节的整数倍时，保留 `0` 或省略该字段；要提供精确字节数，可使用下文的自定义解析。生产发布时建议填写实际 APK 的 MD5。

即使没有更新，也必须提供 `Code`、`UpdateStatus` 和 `VersionCode`，例如：

```json
{"Code": 0, "UpdateStatus": 0, "VersionCode": 2}
```

默认解析同时支持首字母小写的一套字段，如 `code`、`updateStatus`、`versionCode`、`downloadUrl`；同一响应使用一致的命名，不混用两套字段。允许忽略的版本按 `VersionName` 记录，发布新版本时同步更新版本名称；需要重新提示时可调用“清除忽略版本”。

## 请求与解析定制

动态后端可以自行约定检查参数和鉴权。例如，在检查前设置：

```simple
更新.使用POST = 真
更新.置请求参数("versionCode", "1")
更新.置请求头("Authorization", "Bearer 实际令牌")
```

本库不会自动附加本机版本号、包名或渠道；示例中的参数名由后端自行约定，参数值应取实际应用信息。GET 参数加入查询串，POST 默认以 UTF-8 表单发送；将“POST使用JSON”设为真时发送 JSON 对象，参数值仍为文本。请求头同时用于检查和 APK 下载，按两处地址实际需要配置。

已有其它 JSON 协议时，将“自定义解析”设为真，在“解析响应”事件内同步填写传入的“更新信息”，包括有更新、版本号、版本名、更新内容和下载地址等字段；未填写时“有更新”默认为假。事件返回后立即读取信息，不能延后回填。此时“文件大小”使用精确字节数，`0` 表示未提供；自定义解析自行决定是否更新，版本忽略规则仍生效。

## 下载与后台运行

默认使用普通流式下载，文件完成后按提供的大小及 MD5 校验。取消移除未完成文件，清理缓存只处理本实例的文件。

默认离开窗口取消任务；调用“转入后台”后由带通知的前台服务继续。后台完成通过通知请求用户安装，不在后台强行打开界面；进程被结束后不保证自动恢复。

需要暂停续传时，可改用同库的 `simple.library.wsd.xupdateapi.快捷更新器`，在空闲时将“断点续传”设为真。更新信息必须提供真实 APK MD5；调用“暂停下载”并等待“已暂停”事件后，再调用“继续下载”。服务器不支持 Range 时重新完整下载，不保证进程结束后自动恢复。

也可将 `simple.library.wsd.xupdateapi.Aria下载器` 对象通过“置下载器”接入基础更新器；这是可选的组合方式，基础用法不需要创建它。显式设置其它下载器会替换当前策略。

## APK 与运行条件

更新 APK 必须与当前应用具有相同包名，并使用系统认可的更新签名；通常应沿用原签名证书。APK 的实际版本号应高于已安装版本，服务端的 `VersionCode`、`VersionName` 应与该 APK 一致。重新生成不同的调试证书也会导致更新安装失败；签名和安装版本要求最终由系统安装器检查。

强制更新只限制更新框的关闭操作，不能绕过系统安装授权或用户确认。设备须允许该应用请求安装，“已请求安装”仅表示安装界面已打开，不表示安装完成。

组件调用和事件在界面线程执行，默认离开窗口取消任务；显式转入后台后由服务继续。后台下载需要允许本应用显示通知，不提供进程重启自动恢复或静默安装。下载文件保存在应用私有缓存，不发起共享存储授权请求；依赖 AAR 自带的权限声明随上游清单合并。

## 高级接口定制（可选）

普通使用不需要实现以下接口。只有需要替换内部某个环节时，才通过“置检查器”“置解析器”“置提示器”“置下载器”“置网络服务”“置校验器”和“置安装器”替换本实例的对应环节；传入 Simple 的“空”恢复该环节的默认实现。策略只允许在空闲时替换，不修改其它实例或上游全局默认配置。

- 检查器通过检查回调提交响应或已经解析的信息；自定义解析器负责自己的更新判断，不会再强制比较本机版本。
- 网络服务接收请求参数、请求头的 JSON 对象文本，通过检查回调提交原始响应。默认网络不依赖调用方自行初始化 HTTP 客户端。
- 提示器只负责界面，调用方决定何时调用下载更新；自动下载可跳过提示，下载后安装独立控制后续安装请求。
- 下载器通过下载回调提交进度、实际文件或错误，文件完成后仍需通过校验器；默认校验验证文件大小和可选 MD5。
- 安装器返回真只表示已经接管安装请求，不能作为安装成功。系统最终确认和实际安装结果不混为一谈。

独立下载只需填写更新信息中的下载地址和必要校验字段，无需伪造版本号或有更新标记。安装更新可以单独处理可读取的本地 APK。

[运行示例](example/project.properties) 首页提供最简单的基础更新。快捷更新、暂停续传使用独立页面和独立对象；提示样式、流程定制及独立下载安装放在“更多用法”中按需参考。网络操作需填写可访问的服务地址，核心与便捷页面无需互相调用。

示例单元按包组织：`example` 保存主窗口，`example.xupdate` 保存基础更新及流程定制，`example.xupdateapi` 保存快捷更新和续传页面。
