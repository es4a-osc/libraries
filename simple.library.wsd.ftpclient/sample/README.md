# FTP客户端示例

文档类型：使用示例。核对日期：2026-10-16。依据：本库注解接口、清单及当前 Simple 编译器和运行库。适用范围：本目录的 `project.properties`。

先构建本库，再按类库仓库的发布流程安装到所选 SDK，在 ES4A 选择 SDK 入口并刷新类库。本项目已加入工作区的调试项目列表；注册类库后可编译运行。开发期间的构建验证直接使用源码类库目录，没有修改 SDK 清单或安装目录。应用图标使用编译器默认值。

1. 在自己的 FTP 或 SFTP 服务器上准备专用测试目录。默认 FTP；使用 SFTP 时勾选复选框（自动切换常用端口为 22），默认无需填写指纹。填写实际地址、端口、用户名、密码及远程目录，点击登录；首次连接弹框，核对服务器身份后选择“信任并连接”。初始地址和账号为空。SFTP 需要 Android 8.0+，本例使用密码认证。
2. 点击状态目录，检查连接状态和服务器工作目录；点击列表查看远程内容。列表中的大小单位是字节，末项为是否目录。
3. 点击准备文件，在应用内部目录生成 `es4a-ftp.bin`；名称填写该文件名后，点击后台上传，等待结果为真。也可点击同步上传：示例会在线程中调用同步方法。
4. 点击列表确认文件存在，然后点击后台下载或同步下载。下载保存到应用内部的 `ftp-download/`；完成事件或同步返回结果反映传输是否全部成功。
5. 将新名称填写为 `es4a-ftp-renamed.bin`，点击重命名；随后把名称改为新名称，点击删文件，并用列表核对。
6. 将名称填写为 `es4a-ftp-dir`，点击建目录，用列表确认后点击删空目录。目录非空时不递归删除。
7. 点击断开，再点击状态目录确认已断开。

首次连接点击取消或按返回键会拒绝连接；确认超时 60 秒也会结束等待。确认后保存公钥信任，后续及重启应用后连接同一地址、端口不再询问。公钥变化时明确显示新旧指纹，须核实后选择“更新信任并连接”，取消不会覆盖原记录。

“手动指定服务器指纹（高级）”默认关闭；勾选后才显示指纹输入框。填写可信 SHA256:Base64 指纹时严格匹配，错误不会回退到已保存信任。协议与指纹在下一次登录生效；勾选框不会切换已经建立的连接。信任记录属于本应用，清空数据或卸载会删除；账号密码不会写入信任记录。

各项操作需等待完成后再执行下一项。所有输入在主线程捕获；同步网络方法通过窗口自身的后台过程执行，结果由反馈消息事件显示，上传下载也演示组件自带的完成事件，不引入辅助对象单元。

准备文件只覆盖应用内部的 `es4a-ftp.bin`，其内容是 Simple 二进制 WriteString 格式。上传文件名可填写本应用内部已有的其他文件或目录；递归边界见 [类库说明](../README.md)。下载和远程删除、重命名会改变所填目标，操作前核对专用测试目录。

已验证当前源码生成 APK，并通过 Escrcpy 在 Android 14 验证首次取消不发送密码认证、确认登录及目录列表、重启后自动校验、公钥变化时返回拒绝和确认更新、手动错误指纹拒绝。当前版本的文件传输由 49 项真实 SFTP 集成检查覆盖；此前版本的 Android 上传下载和文件管理记录不替代本轮确认交互验证。
